# PMTool 上线检查清单

本清单用于首次发布到 Ubuntu 服务器；完成首次安装后可使用 GitHub Actions 自动发布，具体配置见 [自动部署与回滚.md](自动部署与回滚.md)。

## 发布前

- 服务器安装 Java 17、MySQL 8、Nginx，并创建运行用户和目录：`useradd --system --home /opt/pmtool --shell /usr/sbin/nologin pmtool`、`install -d -o pmtool -g pmtool /opt/pmtool/releases /opt/pmtool/deploy`。
- 创建数据库 `pmtool_db`，并授予应用账户最小权限。
- 配置 S3 兼容对象存储，创建私有 Bucket；应用层严格限制单文件 2 MB。Nginx 请求上限为 3 MB，以容纳 multipart 请求边界开销。
- 将 [`.env.example`](.env.example) 的全部变量写入 `/etc/pmtool/pmtool.env`，设置强 JWT 密钥和初始管理员密码；生产 profile 会拒绝使用缺失的数据库、JWT、管理员或对象存储凭据启动。
- 不将任何生产密码、SSH 凭据或 `.env` 文件提交至 Git。

## 构建与发布

1. 在构建机运行 `cd backend && mvn test && mvn package`。
2. 运行 `cd frontend && npm ci && npm run build`。
3. 安装 `pmtool.service` 至 `/etc/systemd/system/pmtool.service`，执行 `systemctl daemon-reload && systemctl enable pmtool`（首次发布前不启动服务）。
4. 安装 `nginx.conf` 至 Nginx 站点目录，执行 `nginx -t && systemctl reload nginx`。
5. 首次手工发布时，执行 `sh deploy/package-release.sh pmtool-release.tar.gz`，上传该发布包后执行 `deploy/release.sh <发布包> <版本号>`；脚本会写入 `/opt/pmtool/releases/<版本号>`、创建 `/opt/pmtool/current` 软链接，并在发布后启动服务。

## 发布后验证

```sh
cd /opt/pmtool/deploy
chmod +x verify-deployment.sh
./verify-deployment.sh
```

还应使用管理员、项目经理、成员账号各完成一次登录；验证项目权限隔离、文件 2 MB 限制、工时审批、附件下载和通知已读。

## 回滚

执行 `/opt/pmtool/deploy/rollback.sh`，它会恢复 `/opt/pmtool/previous` 指向的版本、重启服务并执行健康检查。数据库迁移只允许向前执行；回滚前须先评估已执行的 Flyway 版本。
