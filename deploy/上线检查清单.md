# PMTool 上线检查清单

自动部署不在当前交付范围。本清单用于首次或人工发布到 Ubuntu 服务器。

## 发布前

- 服务器安装 Java 17、MySQL 8、Nginx，并创建运行用户和目录：`useradd --system --home /opt/pmtool --shell /usr/sbin/nologin pmtool`、`install -d -o pmtool -g pmtool /opt/pmtool/backend /opt/pmtool/frontend`。
- 创建数据库 `pmtool_db`，并授予应用账户最小权限。
- 配置 S3 兼容对象存储，创建私有 Bucket；应用层严格限制单文件 2 MB。Nginx 请求上限为 3 MB，以容纳 multipart 请求边界开销。
- 将 [`.env.example`](.env.example) 的变量写入 `/etc/pmtool/pmtool.env`，设置强 JWT 密钥和初始管理员密码。
- 不将任何生产密码、SSH 凭据或 `.env` 文件提交至 Git。

## 构建与发布

1. 在构建机运行 `cd backend && mvn test && mvn package`。
2. 运行 `cd frontend && npm ci && npm run build`。
3. 将后端 JAR 上传至 `/opt/pmtool/backend/pmtool.jar`，将 `frontend/dist` 内容上传至 `/opt/pmtool/frontend/`。
4. 安装 `pmtool.service` 至 `/etc/systemd/system/pmtool.service`，执行 `systemctl daemon-reload && systemctl enable --now pmtool`。
5. 安装 `nginx.conf` 至 Nginx 站点目录，执行 `nginx -t && systemctl reload nginx`。

## 发布后验证

```sh
cd /opt/pmtool/deploy
chmod +x verify-deployment.sh
./verify-deployment.sh
```

还应使用管理员、项目经理、成员账号各完成一次登录；验证项目权限隔离、文件 2 MB 限制、工时审批、附件下载和通知已读。

## 回滚

保留上一个 JAR 和前端构建目录。若健康检查失败，停止服务，恢复上一个版本文件后执行 `systemctl restart pmtool` 并再次运行验证脚本。数据库迁移只允许向前执行；回滚前须先评估已执行的 Flyway 版本。
