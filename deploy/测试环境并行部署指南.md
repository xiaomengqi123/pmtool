# PMTool Java 测试环境并行部署指南

本文用于将 Vue 3 + Java 17 版 PMTool 部署到测试服务器，同时保留原有 .NET 版 PMTool。文中所有密码、密钥均以占位符表示，严禁写入 Git 仓库或聊天记录。

## 1. 当前部署结果与隔离边界

| 项目 | Java 新系统 | 原 .NET 系统（保留） |
| --- | --- | --- |
| 前端端口 | `8989` | `9000` |
| 后端端口 | `5959` | `5188` |
| systemd 服务 | `pmtool-java.service` | `pmtool.service` |
| 应用目录 | `/opt/pmtool-java` | `/opt/pmtool` |
| 数据库 | `pmtool_db` | 不修改原系统数据库 |
| 附件目录 | `/opt/pmtool-java/uploads` | 不修改原目录 |

**禁止**修改、重启、删除以下旧系统资源：`pmtool.service`、`/opt/pmtool`、Nginx 中监听 `9000` 的站点、后端 `5188`。

新系统访问地址：`http://服务器IP:8989`。后端健康检查为 `http://127.0.0.1:5959/actuator/health`，建议仅在服务器本机访问。

## 2. 部署前检查

以具备 `sudo` 权限的部署账号登录服务器后，确认端口未被新系统以外的程序占用：

```sh
ss -ltn '( sport = :8989 or sport = :5959 )'
systemctl is-active pmtool
systemctl status pmtool --no-pager
```

旧系统应保持 `active`。若 `8989` 或 `5959` 被占用，先停止部署并调整新系统端口，不能覆盖旧系统端口。

检查磁盘空间与 Nginx 配置：

```sh
df -h /
nginx -t
```

## 3. SSH 访问

推荐使用临时部署密钥而不是长期 root 密码。先在部署机生成密钥：

```sh
ssh-keygen -t ed25519 -f ~/.ssh/pmtool_test_deploy -C pmtool-test-deploy
```

使用现有账号密码登录服务器后，将公钥追加到部署账号的 `authorized_keys`：

```sh
mkdir -p ~/.ssh
chmod 700 ~/.ssh
cat ~/.ssh/pmtool_test_deploy.pub >> ~/.ssh/authorized_keys
chmod 600 ~/.ssh/authorized_keys
sshd -t
```

验证密钥登录：

```sh
ssh -i ~/.ssh/pmtool_test_deploy root@服务器IP 'echo SSH_OK'
```

测试结束后删除对应的单行公钥，或撤销专用部署账号权限。

## 4. 安装运行依赖

服务器需要 Java 17、Nginx、MySQL 客户端。Nginx 若已用于旧系统，不应重装或删除配置。

```sh
sudo apt-get update
sudo apt-get install -y openjdk-17-jre-headless mysql-client
java -version
nginx -v
```

应看到 Java `17.x`。本项目只需要 JRE 运行已构建的 JAR；构建在本地或 CI 完成。

## 5. 创建独立数据库与运行账号

创建独立 Linux 服务账号和目录：

```sh
sudo useradd --system --home /opt/pmtool-java --shell /usr/sbin/nologin pmtool-java || true
sudo install -d -o pmtool-java -g pmtool-java -m 0750 \
  /opt/pmtool-java/releases /opt/pmtool-java/deploy /opt/pmtool-java/uploads
sudo install -d -o root -g root -m 0700 /etc/pmtool-java
```

创建数据库与应用账号。若 MySQL 是普通服务，可按以下方式连接：

```sql
CREATE DATABASE pmtool_db CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
CREATE USER 'pmtool_java'@'%' IDENTIFIED BY '<强数据库密码>';
GRANT SELECT, INSERT, UPDATE, DELETE, CREATE, ALTER, INDEX, DROP, REFERENCES
  ON pmtool_db.* TO 'pmtool_java'@'%';
FLUSH PRIVILEGES;
```

当前测试服务器的 MySQL 由 Docker 容器提供，宿主机没有 MySQL socket；需在容器内执行 SQL，例如：

```sh
docker ps --format 'table {{.Names}}\t{{.Image}}'
docker exec -it <mysql容器名> mysql -uroot -p
```

不要使用 `docker inspect` 输出环境变量值，也不要记录 MySQL root 密码。

验证应用账号：

```sh
mysql -h 127.0.0.1 -u pmtool_java -p pmtool_db -e 'SELECT DATABASE();'
```

## 6. 服务器环境变量

创建 `/etc/pmtool-java/pmtool.env`，权限必须为 `0600`：

```dotenv
DB_HOST=127.0.0.1
DB_PORT=3306
DB_NAME=pmtool_db
DB_USERNAME=pmtool_java
DB_PASSWORD=<强数据库密码>
JWT_SECRET=<至少32字节的随机密钥>
INITIAL_ADMIN_USERNAME=admin
INITIAL_ADMIN_PASSWORD=<测试环境初始密码>
FILE_STORAGE_DIR=/opt/pmtool-java/uploads
CORS_ALLOWED_ORIGINS=http://服务器IP:8989
```

```sh
sudo chmod 600 /etc/pmtool-java/pmtool.env
sudo chown root:root /etc/pmtool-java/pmtool.env
```

建议使用以下方式生成随机值，输出后仅写入服务器文件：

```sh
openssl rand -hex 32   # 数据库密码
openssl rand -hex 48   # JWT_SECRET
```

附件存储为服务器私有目录；不能配置为 Nginx 静态目录。上传和下载均由后端完成权限校验，单文件最大 2 MB。

## 7. systemd 与 Nginx 配置

创建 `/etc/systemd/system/pmtool-java.service`：

```ini
[Unit]
Description=PMTool Java Spring Boot API
After=network.target

[Service]
Type=simple
User=pmtool-java
WorkingDirectory=/opt/pmtool-java/current/backend
EnvironmentFile=/etc/pmtool-java/pmtool.env
ExecStart=/usr/bin/java -jar /opt/pmtool-java/current/backend/pmtool.jar --spring.profiles.active=prod
Restart=always
RestartSec=5

[Install]
WantedBy=multi-user.target
```

创建 `/etc/nginx/sites-available/pmtool-java`：

```nginx
server {
    listen 8989;
    server_name _;
    root /opt/pmtool-java/current/frontend;
    index index.html;
    client_max_body_size 3m;

    location /api/ {
        proxy_pass http://127.0.0.1:5959;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }

    location / {
        try_files $uri $uri/ /index.html;
    }
}
```

启用新配置，不修改旧站点：

```sh
sudo ln -sfn /etc/nginx/sites-available/pmtool-java /etc/nginx/sites-enabled/pmtool-java
sudo systemctl daemon-reload
sudo systemctl enable pmtool-java
sudo nginx -t
sudo systemctl reload nginx
```

## 8. 本地构建与发布包

在仓库根目录执行：

```sh
cd backend
mvn test
mvn package

cd ../frontend
npm ci
npm run build
```

正常情况下可在 Git Bash / Linux / macOS 上执行：

```sh
sh deploy/package-release.sh pmtool-release.tar.gz
```

Windows 未安装 Git Bash 时，可使用任意支持 `tar` 的工具将以下内容打为 `.tar.gz`，且压缩包根目录必须为：

```text
backend/pmtool.jar
frontend/index.html
frontend/assets/...
deploy/release.sh
deploy/rollback.sh
deploy/verify-deployment.sh
```

上传前计算校验值：

```sh
sha256sum pmtool-release.tar.gz
```

上传完成后在服务器再次执行 `sha256sum`，两端必须完全一致。网络不稳定时可拆分为小文件传输，服务器合并并校验后再替换发布包；绝不能解压校验失败或未完成上传的包。

## 9. 首次发布

上传包到 `/opt/pmtool-java/pmtool-release.tar.gz`。首次发布时，可从包内提取发布脚本并运行：

```sh
cd /opt/pmtool-java
tar -xOzf pmtool-release.tar.gz deploy/release.sh > /tmp/pmtool-java-release.sh
chmod 700 /tmp/pmtool-java-release.sh

PMTOOL_ROOT=/opt/pmtool-java \
PMTOOL_USER=pmtool-java \
PMTOOL_SERVICE=pmtool-java \
/tmp/pmtool-java-release.sh /opt/pmtool-java/pmtool-release.tar.gz <版本号>
```

`<版本号>` 可使用 Git 短提交号，例如 `git rev-parse --short HEAD`。首次启动会执行 Flyway 建表，并可能需要十余秒；若脚本的即时健康检查尚未成功，先等待后再手动验证，不要误操作旧系统。

## 10. 发布后验证

```sh
systemctl is-active pmtool-java
curl -fsS http://127.0.0.1:5959/actuator/health
curl -fsSI http://127.0.0.1:8989/ | head -n 1
ss -ltn '( sport = :8989 or sport = :5959 )'
```

外部验证：

1. 打开 `http://服务器IP:8989`。
2. 使用 `/etc/pmtool-java/pmtool.env` 中的初始管理员登录。
3. 创建项目、任务与成员，检查权限隔离。
4. 上传不超过 2 MB 的附件并下载验证。
5. 确认旧系统 `http://服务器IP:9000` 仍可访问。

排查日志：

```sh
journalctl -u pmtool-java -n 200 --no-pager
journalctl -u pmtool-java -f
nginx -t
```

## 11. 回滚与卸载

正常发布后，若已有前一 Java 版本，可回滚 Java 系统：

```sh
PMTOOL_ROOT=/opt/pmtool-java \
PMTOOL_SERVICE=pmtool-java \
/opt/pmtool-java/deploy/rollback.sh
```

Flyway 数据库迁移不会自动回滚；涉及破坏性迁移前必须先备份 `pmtool_db`。首次发布没有前一 Java 版本时无法自动回滚，可停止新服务而不影响旧系统：

```sh
sudo systemctl stop pmtool-java
```

不再需要测试环境时，应先备份数据库与附件目录，再删除新系统资源；不得删除 `/opt/pmtool` 或 `pmtool.service`。

## 12. GitHub 与安全清理

当前 GitHub Actions 的 `verify` 只构建和测试，不会自动发布。启用自动部署前，需要单独配置专用部署用户、SSH 私钥、主机指纹和 GitHub Environment Secrets。

测试完成后至少完成以下操作：

- 修改初始管理员密码；
- 删除临时 SSH 公钥；
- 清理 `/tmp/pmtool-java-release.sh` 与临时发布包；
- 备份 `/opt/pmtool-java/uploads` 和 `pmtool_db`；
- 确认 `/etc/pmtool-java/pmtool.env` 不可被普通用户读取；
- 将本地已完成但未同步的 Git 提交推送到 GitHub。
